# Codex 프론트엔드 리뷰 스킬 설계

## 목적

`frontend-review`는 기존 프론트엔드 변경에서 실제 결함과 회귀를 근거 중심으로 찾는 독립 리뷰 스킬이다. 구현 스킬과 역할을 분리해 작성자의 가정을 반복하지 않도록 한다.

## 범위

다음 요청에 사용한다.

- 프론트엔드 코드 또는 diff 리뷰
- UI 기능 변경의 회귀 검토
- strict 산출물과 실제 구현의 대조

다음 작업은 포함하지 않는다.

- 사용자가 별도로 요청하지 않은 코드 수정
- 포맷이나 단순 취향의 지적
- 근거 없는 리팩터링 또는 아키텍처 제안
- 백엔드 전용 코드 리뷰

## 구조

```text
skills/frontend-review/
├── SKILL.md
└── agents/openai.yaml
```

첫 버전은 별도 reference, 템플릿, 스크립트를 만들지 않는다. 반복적으로 누락되는 리뷰 유형이 확인될 때만 추가한다.

## 리뷰 절차

1. 저장소 지침, 사용자 요청, 최종 diff, 관련 테스트를 확인한다.
2. strict 산출물이 있으면 수용 기준과 추적 근거를 실제 변경과 대조한다.
3. 기능 오류, 회귀, UI 상태 누락, 경쟁 상태, 접근성, 반응형, 서버·클라이언트 경계를 검토한다.
4. 재현 가능하거나 코드로 입증할 수 있는 항목만 finding으로 작성한다.
5. finding을 P1, P2, P3 순서로 정렬한다.
6. finding이 없으면 검토한 범위와 남은 검증 공백을 밝힌다.

## 심각도

- `P1`: 보안, 데이터 손상, 핵심 흐름 실패처럼 배포를 막아야 하는 문제
- `P2`: 실제 사용자에게 영향을 주는 기능 또는 접근성 회귀
- `P3`: 제한된 조건에서 발생하는 낮은 위험의 문제

확신이 부족한 항목은 finding으로 단정하지 않고 확인이 필요한 가정으로 분리한다.

## Finding 형식

각 finding은 다음 정보를 포함한다.

- 심각도와 문제 요약
- 파일과 가능한 경우 정확한 줄
- 문제라고 판단한 근거
- 사용자 또는 시스템에 미치는 영향

수정 방법은 문제를 이해하는 데 필요할 때만 짧게 제시한다. 상세 구현 계획을 만들지 않는다.

## 기존 스킬과의 관계

`frontend-workflow`는 계획, 구현, 검증을 수행한다. `frontend-review`는 완성된 변경을 독립적으로 읽고 문제를 보고한다.

Strict 문서가 있으면 활용하지만 새 문서를 만들거나 strict 형식을 요구하지 않는다. 문서가 없으면 요청과 diff를 기준으로 일반 리뷰를 수행한다.

## 검증 기준

- Codex 스킬 구조 검증을 통과한다.
- 코드 리뷰 요청에는 선택되고 일반 구현 요청에는 선택되지 않는 설명을 갖는다.
- 코드 변경 없이 finding 중심으로 응답하도록 명시한다.
- 스타일 취향과 자동 도구가 처리하는 항목을 제외한다.
- finding이 없을 때도 검증 공백과 남은 위험을 보고한다.
