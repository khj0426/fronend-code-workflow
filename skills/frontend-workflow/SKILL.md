# 프론트엔드 워크플로

사용자가 관찰할 수 있는 결과에서 출발하고 저장소의 기존 패턴과 도구를 우선한다.

## 작업 강도

### 작은 변경

상태 전이나 공개 인터페이스를 바꾸지 않는 문구, 스타일, 정적 콘텐츠 변경이다. 관련 코드를 확인하고 최소 변경과 집중된 검증만 수행한다. 계획 문서를 만들지 않는다.

### 일반 기능

사용자 입력, 상태, 내비게이션, 비동기 동작 또는 여러 UI 상태가 포함된 변경이다.

1. [references/specification.md](references/specification.md)를 읽는다.
2. 사용자 시나리오, 관련 UI 상태, 수용 기준, 제외 범위를 제안한다.
3. 선택 사항이 요청에 명확하지 않으면 구현 전에 승인을 받는다.
4. 기존 패턴을 따라 검증 가능한 작은 수직 단위로 구현한다.
5. [references/verification.md](references/verification.md)를 읽고 관련 코드와 브라우저 동작을 검증한다.

### 고위험 변경

영향받는 소비자, 호환성, 롤백 조건을 확인하고 대안과 구현 순서에 대한 승인을 받는다. 작업 중 공개 API, 데이터 계약, 새 의존성 또는 롤백 제약을 발견하면 범위 확대를 알린다.

다음 작업에는 strict 모드를 자동으로 추천한다.

- 인증, 권한, 결제 또는 개인정보 처리
- 여러 소비자가 있는 데이터 계약 또는 단계적 마이그레이션
- 호환성 유지나 명시적인 롤백이 필수인 작업
- 사용자가 요구사항과 검증의 추적을 요청한 작업

추천할 때 추가되는 산출물과 비용을 한두 문장으로 설명한다. 추천은 승인이 아니며, 거절하면 일반 고위험 절차로 진행한다.

## Strict 모드

사용자가 `strict`를 명시하거나 자동 추천을 승인했을 때만 [references/strict-mode.md](references/strict-mode.md)를 읽는다. 승인 전에는 문서나 추적 파일을 만들지 않는다.

## 완료

사용자 관점의 변경, 수행한 검사, 검증하지 못한 동작과 남은 위험을 보고한다.
