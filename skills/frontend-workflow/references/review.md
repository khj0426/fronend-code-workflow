# 리뷰

구현과 검증을 마친 뒤 이 문서를 읽는다. 기억나는 파일만 보지 말고 최종 diff 전체를 검토한다.

## 의도와 비교한다

- 요청한 결과가 모두 구현됐는가?
- 사용자가 요청하지 않은 동작이 추가됐는가?
- 제외한 범위가 여전히 제외돼 있는가?
- 관련 로딩, 빈 결과, 오류, 복구 상태를 처리했는가?

## 회귀를 찾는다

- 공개 props, 라우트, URL, 저장소 키, 데이터 형태
- 포커스 이동, 키보드 조작, 레이블, 상태 알림
- 좁은 레이아웃, 긴 콘텐츠, 현지화, 테마 차이
- 중복 요청, 오래된 상태, 정리 작업, 경쟁 상태
- 서버와 클라이언트 경계, 하이드레이션, 브라우저 전용 API
- 제거한 동작을 사용하는 코드나 문서

## 복잡성을 의심한다

새 의존성, 추상화, 전역 상태, effect 또는 설정 변경이 요청한 결과에 꼭 필요한지 확인한다. 근거 없는 복잡성은 아키텍처로 설명하기보다 제거하는 것을 우선한다.

## 검증 근거를 확인한다

통과했다고 보고하는 모든 검사가 실제로 실행되고 성공적으로 끝났는지 확인한다. 일부 출력, 실행 중인 프로세스 또는 관련 없는 성공 검사를 근거로 사용하지 않는다.

## 결과를 인계한다

결과부터 말한다. 의미 있는 검증 결과와 남은 위험을 밝힌다. 사용자가 확인하거나 작업을 이어가는 데 도움이 될 때만 파일을 언급한다. 아직 요청받지 않은 행동에만 추가 승인을 요청한다.
