# 엄격 모드

수용 기준을 구현과 검증까지 추적해야 할 때 사용한다.

## 산출물

저장소 관례가 없다면 다음 위치에 만든다.

```text
docs/frontend-workflow/<feature-slug>/
├── spec.md
├── plan.md
└── trace.json
```

중요한 관찰, 선택한 결정 또는 버린 대안이 생긴 경우에만 선택적으로 `journal.md`를 추가한다. 초기 파일은 `assets/templates/`에서 복사하고 안내 문구를 실제 내용으로 교체한다.

## 명세와 계획

`spec.md`에는 사용자 시나리오, `AC-001` 형식의 관찰 가능한 수용 기준, 관련 UI 상태, 제외 범위를 작성한다.

`plan.md`에는 각 수직 작업 단위가 처리하는 수용 기준과 검증 방법을 적는다. 새 의존성, 공개 인터페이스, 데이터 이전, 호환성 또는 롤백 제약도 포함한다.

명세와 계획 초안을 함께 제시하고 한 번의 승인을 받은 뒤 구현한다. 구현 중 의미나 범위가 바뀌면 두 문서를 먼저 갱신하고 사용자에게 알린다.

## 추적

`trace.json`에 모든 수용 기준의 상태와 근거를 기록한다.

- `pending`: 아직 구현 또는 검증되지 않았다.
- `verified`: 구현 파일과 테스트 또는 수동 검증 근거가 있다.
- `excluded`: 합의에 따라 제외했으며 이유가 있다.

검증하지 않은 항목을 `verified`로 표시하지 않는다. 파일은 저장소 루트 기준 상대 경로로 기록한다.

## 검사

저장소 루트에서 실행한다.

```text
python3 <skill-path>/scripts/check_trace.py docs/frontend-workflow/<feature-slug>/trace.json --root .
```

검사는 JSON 구조, ID, 상태, 근거, 파일 존재 여부를 확인한다. 테스트 내용이나 구현 품질은 일반 검증과 최종 diff 리뷰로 확인한다.
